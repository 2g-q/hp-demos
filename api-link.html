サービス 料金 事例

サービス同士を、つなぎます。

通販サイトの注文を配送会社へ。社内の表計算をチャットへ。人が毎日コピーして貼り替えている受け渡しを、機械に代わってもらいます。

相談内容を送るほかの制作例を見る

実際につないだ例

いずれも実際にお受けした仕事です。会社名は伏せています。

通販の注文を、配送会社の送り状発行まで

通販サイト注文データ
→
整形配送会社の様式へ
→
送り状発行そのまま登録

困っていたこと注文が入るたびに管理画面から一覧を落とし、配送会社の様式に貼り替えて、送り状を1件ずつ登録していました。年末年始は月500件規模になります。

つないだもの通販サイトから注文を取り出し、配送会社の様式に整えて、送り状発行のシステムへ登録するところまでを1本にしました。ログインもこちらで通します。

どうなったかログインしていない状態から16.8秒で登録まで終わります。人が画面を操作する工程はありません。同じ注文を二重に登録しないよう、登録済みのものは止める仕組みを入れてあります。

注文の一覧を、倉庫へのチャット通知まで

通販サイト当日の注文
→
表計算出荷指示の形へ
→
チャット倉庫へ自動送信

困っていたこと出荷の指示を人が毎日まとめて送っていました。送り忘れるとその日の出荷が止まります。

つないだもの決まった時刻に当日の注文を取り出し、出荷指示の形にまとめて、倉庫のチャットへ送るようにしました。処理はクラウド側で動きます。

どうなったかパソコンを開いていなくても決まった時刻に流れます。注文300件を取り出して送るところまで、人の操作なしで通ることを実測しています。

サービスの利用状況を、管理画面で見えるように

AIの提供元応答の記録
→
データベース待ち時間を蓄積
→
管理画面数字で表示

困っていたこと「AIの応答が遅い」という声はあるものの、何が原因なのか分からない状態でした。心当たりで直しても、直ったかどうかも分かりません。

つないだもの呼び出しごとに、待ち時間と使った量と提供元からの上限情報を記録するようにし、管理画面から見えるようにしました。

どうなったか遅くなるのは前の呼び出しから60秒以内に呼んだときだけだと分かりました（60秒以内は中央値21.3秒、それより空けば2.6秒）。原因が数字で見えたので、無駄な重複呼び出しを1回から0回にできました。

つなげる先

つなぎ口が公開されているものはそのまま、公開されていないものはログインして画面から操作する形でつなぎます。
